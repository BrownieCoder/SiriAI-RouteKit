# 唯一源、版本锁与更新

唯一编辑源为 [BrownieCoder/proxy-rulesets](https://github.com/BrownieCoder/proxy-rulesets)中的：

- `rules/siri-ai-domains.txt`：排序后的裸精确域名。
- `rules/siri-ai-provenance.json`：逐域证据。
- `research/SiriAI-audit.json`：本次 18 条候选的完整审计。

本仓库导入三个已提交文件，不复制其它 provider、私人节点或配置。导入后的域名清单是本项目本地生成基准，编辑权仍属于唯一源仓库；不要在两处各自加域名。

## 首次导入或批准更新

在本仓库根目录运行，`/公开源checkout` 换成自己的公开源工作目录：

```sh
python3 scripts/rules.py import --source /公开源checkout
python3 scripts/rules.py validate --source /公开源checkout
python3 -m unittest discover -s tests
git diff --check
```

导入器要求源仓库 `origin` 标识为上述 GitHub 项目，读取真实 `HEAD` 的三个文件；这三个工作区文件必须与提交内容相同。不会打印远程设置的实际值，不会扫描私人配置。其它无关文档未提交不影响导入。

`source.lock.json` 记录来源 URL、完整提交号、GPL-2.0-only 与每个文件 SHA256。导入后自动生成客户端规则、规则模块、三个示例与安装文件哈希清单；所有改动应审查完整 diff。若上游名单改变而未重新核验当前 README/审计结论，不应仅为了通过脚本直接提交。

## 三种检查不能混为一谈

| 命令 | 能证明什么 | 不能证明什么 |
|---|---|---|
| `validate` | 本仓库锁定快照、来源结构与生成物一致 | 上游最新版本没有变化 |
| `validate --source /公开源checkout` | 指定本地 checkout 的身份、锁定提交内容及当前 HEAD 三个文件均一致；源文件未改动 | GitHub 远程最新 HEAD 与本地相同 |
| 经授权更新公开源后再验证 | 已更新的本地 HEAD 与本项目一致 | Apple 功能可用或客户端实测成功 |

工具不自动 fetch、push 或访问网络；CI 也只验证锁定快照。源身份检查核对的是本地 `origin` 配置标识，不能当作密码学签名或可信远程认证。若拿到来源不可信的 checkout，先自行核对公开来源，不能仅靠设置一个相同的 origin 欺骗信任。

重新生成已有锁定快照：

```sh
python3 scripts/rules.py generate
git diff --exit-code -- rules examples modules install/assets.json
```

`generate` 在写出前检查输入 SHA256，不能用于掩盖手改 canonical 文件。校验只覆盖项目采用的简单格式，实际 Mihomo 解析和 Shadowrocket 导入要另行验证。

## 安装资产与发布边界

`python3 scripts/rules.py generate` 还会生成：

- `modules/siri-ai.module`：只含 `[Rule]` 和规范域名对应的 `DOMAIN,…,PROXY`。
- `examples/clash-remote.yaml`：独立无节点示例，内联同一份精确规则，无本地 provider 依赖。显式 `proxies: []` 满足 Verge 远程配置的键存在检查。
- `install/assets.json`：每个生成文件的 SHA256；由生成器计算，禁止手改。规则数量、顺序与字节级一致性仍由 `validate` 检查。

`install/` 是纯 HTML/CSS/JS，没有构建或第三方依赖。绿白配色、系统字体、单列客户端选择；按钮说明对应真实行为。页面只请求本项目公开清单和固定 GitHub raw 文件；不接受 URL 参数指定下载目标，不形成开放重定向。远程内容与清单哈希匹配后才启用唤起按钮；Shadowrocket 自动尝试一次，Clash 必须点击已标明影响的按钮。浏览器唤起未必允许，仍保留复制和手动步骤。

本地验证：

```sh
python3 scripts/rules.py validate
python3 -m unittest discover -s tests
node --test tests/install.test.cjs
python3 scripts/rules.py generate
git diff --check
```

已提交后可运行 `git diff --exit-code -- rules examples modules install/assets.json` 检查重新生成无差异。Node 仅用于测试安装页交互；页面本身无 npm 依赖。

仓库身份与 `main` 默认分支已通过匿名 GitHub API 确认。以下是发布目标，**核验时尚未上线**：

### 发布后的验收（需另行授权）

最小托管方式是 GitHub Pages 从 `main` 根目录发布现有静态文件，不新增需要 `pages: write` / `id-token: write` 的 Actions workflow。本任务不更改 Pages setting；必须先获得托管授权。

发布后依次检查：远程模块与示例 HTTP 200 且哈希等于本地生成物 → Pages 各页/JS/CSS/清单 HTTP 200 → README 主入口改为已验证的 HTTPS 安装页 → 真机确认下载、启用和规则命中。若域名或网络不可达，先保留文件导入入口，不能宣称闭环完成。下载成功、scheme 唤起、规则命中、Siri 功能成功分别记录。

本地预览可在项目目录运行 `python3 -m http.server 8765 --bind 127.0.0.1`，浏览 `http://127.0.0.1:8765/install/`。预览仍检查真实公开 raw；尚未发布时导入按钮按设计保持不可用。只服务公开项目目录，不能把父级私人配置目录作为服务器根目录。
