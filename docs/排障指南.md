# 按顺序排障

先查设备 → 系统版本 → 设备销售地区 → Apple 账户地区与实际所在地 → 设备/Siri 语言 → 模型下载状态 → Siri AI Beta 等待名单/开放状态 → 最后查网络分流。

这是本项目根据官方条件整理的排查方法，不是 Apple 对每一种报错的唯一诊断。资格依据见[官方要求汇总](设备与账号要求.md)，核验于 2026-09-22；本项目未做设备功能实测。

| 症状 | 优先检查 | 可能原因 | 下一步 |
|---|---|---|---|
| 完全看不到 Apple Intelligence | 设备、系统、销售地区、Apple 账户、语言 | 硬件或地区等资格不符 | 对照官方页面；不要先换节点 |
| 有 Apple Intelligence，没有 Siri AI Beta | 27 系列版本、英语、地区和 Beta 开放状态 | 一般功能与 Beta 条件不同 | 找设置 → Siri → Try Siri AI (Beta)，缺少入口则回查资格 |
| 已加入等待名单 | 页面明确显示等待还是下载 | 尚未获准 | 无官方固定时长；排队不能证明网络故障 |
| 一直下载模型 | 先看空间、模型/语言状态、Wi-Fi 连通性 | 空间不足或下载连接失败，也可能仍在排队 | 对照当前 8/14GB 等要求，核对实际失败连接；查看 [Apple 系统状态](https://www.apple.com/support/systemstatus/) |
| 改了语言后暂时不可用 | 新语言模型、两处语言是否一致 | 新模型尚未准备好 | 等待模型完成，不反复切换语言 |
| Shadowrocket 已连上但不能用 | 使用的配置、全局路由、规则测试、策略组、出口与 DNS | 连接代理不等于规则命中，也可能资格未过 | 重新编译配置副本，核对请求日志，再查资格 |
| Mihomo 规则不命中 | provider 加载、路径、规则次序、组名 | Apple DIRECT/China 或宽泛 provider 提前匹配 | 将 SiriAI 引用放在它们前面，安全规则仍优先 |
| 规则命中但 UDP 走了别处 | 节点的 UDP 支持与最终链 | Mihomo 会跳过不支持 UDP 的代理继续匹配 | 使用兼容出口并看最终连接；不盲目关闭 QUIC |
| 换节点仍失败 | 前七层资格与状态 | 网络可能从来不是主因 | 停止无意义换节点，记录官方页面与状态差异 |
| Siri 没有声音或唤醒词无反应 | 语音唤醒、声音识别、回应选项、音量 | 本地语音设置 | 按 Apple 的 [Siri 故障指南](https://support.apple.com/zh-cn/105037)处理 |
| ChatGPT 扩展不可用 | 扩展开关与服务自己的地区支持 | 扩展具有独立可用性边界 | 不用它的结果代替 Apple Intelligence 或 Siri AI Beta 的启用判据 |

网络依据：[Apple 主机/端口](https://support.apple.com/en-us/101555)、[Mihomo 路由文档](https://wiki.metacubex.one/config/rules/)。某些 VPN 或受管理描述文件可能影响 Siri，见上述 Apple Siri 故障指南。

## 怎么记录一次有效的测试？

1. 在设备上确认目标功能的设置状态，分清“无资格”“排队”“下载”“已启用”。
2. 记录本地时间，发送不含姓名、联系人或私人内容的简短请求。
3. 在代理连接记录里只记录公开目标域名、匹配规则、策略名、TCP/UDP 与错误类别；不要公开实际节点地址或完整日志。
4. 分开记“功能状态”“路由命中”“请求结果”。不能从网络通反推账号必有资格。

观察不到五个域名不代表必须增加规则：请求可能本地处理、复用连接、走其他依赖或尚未发起。候选域名需要脱敏可复现证据才能审计接纳。不要以整个 `apple.com`、`icloud.com`、Cloudflare CDN 或 `DOMAIN-KEYWORD,siri` 掩盖原因。

## 回退

Shadowrocket 先关闭或移除 Siri AI 模块，再按提示重载；仅切换主配置不一定关闭模块。手动修改副本时重新选择原配置并编译；Mihomo 重新使用保存的原配置或撤销本次副本中的 provider 引用。不要删除订阅/节点，也不要覆盖唯一一份私人配置。本项目工具只在自己的仓库内生成公开文件，不会替你修改正在使用的配置。
